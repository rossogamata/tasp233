## 1. Поняття Docker Compose

**Docker Compose** — інструмент для опису та запуску багатоконтейнерних застосунків. Замість окремого запуску кожного контейнера конфігурація всього проєкту зберігається у YAML-файлі, зазвичай `compose.yaml`.

У цьому занятті проєкт складається з двох сервісів:

| Сервіс | Призначення | Образ | Доступ |
|---|---|---|---|
| `web` | Віддає HTML і проксуює API-запити | NGINX, збирається з `web/Dockerfile` | `http://localhost:8080` |
| `api` | Повертає JSON-відповідь і health status | Python, збирається з `api/Dockerfile` | Лише всередині Compose-мережі |

Основні поняття:

- **Service** — опис контейнера в Compose-файлі.
- **Project** — усі сервіси, мережі та volumes одного `compose.yaml`.
- **Network** — внутрішня мережа, у якій сервіси знаходять один одного за іменем, наприклад `http://api:8000`.
- **Volume** — постійне сховище, яке зберігається після перезапуску контейнера.
- **Build** — створення образу за Dockerfile.
- **Healthcheck** — автоматична перевірка, чи готовий сервіс приймати запити.

> Сучасна команда має назву `docker compose` із пробілом. Старий варіант `docker-compose` із дефісом може бути встановлений окремо, але в цьому занятті використовується Docker Compose v2.

## 2. Docker Compose файл

Відкрийте [compose.yaml](compose.yaml):

```yaml
services:
  web:
    build: ./web
    ports:
      - "8080:80"
    depends_on:
      api:
        condition: service_healthy
    networks:
      - lesson-network

  api:
    build: ./api
    expose:
      - "8000"
    environment:
      APP_MESSAGE: "Вітаємо у Docker Compose!"
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"]
    networks:
      - lesson-network
```

Пояснення ключових полів:

| Поле | Призначення |
|---|---|
| `services` | Початок опису всіх сервісів проєкту. |
| `build` | Каталог, у якому Compose шукає Dockerfile і build context. |
| `ports` | Публікація порту у форматі `порт_хоста:порт_контейнера`. |
| `expose` | Документує внутрішній порт без публікації назовні. |
| `depends_on` | Визначає залежність запуску одного сервісу від іншого. |
| `condition: service_healthy` | Дозволяє стартувати `web` після успішного healthcheck `api`. |
| `environment` | Передає змінні середовища в контейнер. |
| `healthcheck` | Перевіряє працездатність сервісу. |
| `networks` | Під'єднує сервіси до спільної мережі. |
| `volumes` | Монтує постійне сховище або локальний каталог. |
| `restart` | Визначає політику автоматичного перезапуску. |

Compose автоматично створює мережу проєкту. Тому з контейнера `web` сервіс `api` доступний за DNS-іменем `api`. Адреса `localhost` усередині `web` означала б сам контейнер `web`, а не `api`.

## 3. Збірка проєкту за допомогою Docker Compose

Відкрийте термінал і перейдіть до каталогу заняття:

```bash
cd Lesson2_6
```

### Перевірка конфігурації

```bash
docker compose config
```

Команда об'єднує та перевіряє конфігурацію Compose без запуску контейнерів.

### Збірка образів

```bash
docker compose build
```

Compose окремо збирає образи для `web` і `api` за відповідними Dockerfile.

### Запуск проєкту

```bash
docker compose up --detach
```

Після запуску відкрийте [http://localhost:8080](http://localhost:8080). Натисніть кнопку **Отримати відповідь** і переконайтеся, що frontend отримує повідомлення від API.

Перевірте стан сервісів:

```bash
docker compose ps
docker compose ps --all
```

### Перегляд логів

```bash
docker compose logs
docker compose logs --follow web
docker compose logs --follow api
```

### Виконання команд усередині сервісу

```bash
docker compose exec web nginx -v
docker compose exec api python --version
```

### Перезапуск і зупинка

```bash
docker compose restart
docker compose stop
docker compose start
```

`stop` зупиняє контейнери, але не видаляє їх. Щоб зупинити та видалити контейнери й мережу проєкту:

```bash
docker compose down
```

Щоб також видалити образи, створені Compose:

```bash
docker compose down --rmi local
```

Не використовуйте `down --volumes`, якщо потрібно зберегти дані volume.

## Самостійна робота

Працюйте в каталозі `Lesson2_6`.

### Завдання 1. Дослідження Compose-проєкту

1. Перегляньте структуру `compose.yaml`, `web/` та `api/`.
2. Поясніть, чому порт `8080` опублікований тільки для `web`.
3. Знайдіть, як `web` звертається до `api` за іменем сервісу.
4. Поясніть, навіщо потрібні `depends_on` і `healthcheck`.

### Завдання 2. Зміна проєкту

1. Змініть значення `APP_MESSAGE` у `compose.yaml` на власний текст.
2. Змініть заголовок або кольори у `web/index.html`.
3. Додайте до API нове поле JSON, наприклад `group` або `author`.
4. Перебудуйте образи та перезапустіть проєкт:

```bash
docker compose down
docker compose up --build --detach
```

5. Перевірте результат у браузері, командою `docker compose ps` і через логи.

### Завдання 3. Додатковий сервіс

Додайте третій сервіс до `compose.yaml` на вибір:

- Redis для кешування;
- PostgreSQL для зберігання даних;
- окремий NGINX або статичний frontend;
- власний сервіс на Python.

Для додаткового сервісу потрібно вказати образ або `build`, мережу, необхідні змінні середовища та залежності.

### Що здати

- змінений `compose.yaml`;
- змінені файли застосунку;
- скриншот працюючого проєкту у браузері;
- результат `docker compose ps`;
- фрагмент логів `docker compose logs`;
- коротке пояснення різниці між `docker compose build`, `up`, `exec`, `logs` і `down`.
