## 1. Вступне опитування

Перед початком самостійної роботи викладач проводить коротке опитування за матеріалами заняття 2/1. Курсант відповідає на одне або кілька питань і наводить практичний приклад.

1. Чому контейнер зазвичай має один головний процес?
2. Чому дані в контейнері не варто зберігати без volume?
3. Чим `docker stop` відрізняється від `docker kill`?
4. Що станеться, якщо два контейнери спробують опублікувати один і той самий порт хоста?
5. Чому образ на базі Alpine не завжди автоматично кращий за Debian або Ubuntu?
6. Чи є контейнер достатнім захистом від шкідливого коду? Обґрунтуйте відповідь.
7. Які переваги дає опис інфраструктури у `Dockerfile` порівняно з ручним налаштуванням сервера?

## 2. Самостійна робота

Працюйте з підготовленим вебзастосунком у каталозі `Lesson2_3/site`. Застосунок має Hello Kitty-inspired дизайн, анімовані елементи та можливість змінити прізвище курсанта.

### Завдання 1. Кастомізація застосунку

1. Відкрийте файл `site/index.html`.
2. Знайдіть рядок `const defaultSurname = "Курсант";` і замініть значення на власне прізвище.
3. Змініть щонайменше три елементи: заголовок, колір, текст картки або футер.
4. Перевірте, що поле введення змінює привітання після натискання кнопки.

### Завдання 2. Створення та запуск образу

Виконуйте команди з каталогу `Lesson2_3`, де розташований `Dockerfile`:

```bash
docker version
docker run --rm hello-world
docker build --tag surname-web:1.0 .
docker image ls surname-web
docker run --detach --name surname-web-container --publish 8090:80 surname-web:1.0
docker ps
```

Відкрийте у браузері `http://localhost:8090` та перевірте роботу сторінки. Додатково виконайте:

```bash
curl http://localhost:8090
```

Після зміни дизайну створіть другу версію образу:

```bash
docker build --tag surname-web:2.0 .
docker stop surname-web-container
docker rm surname-web-container
docker run --detach --name surname-web-container --publish 8090:80 surname-web:2.0
```

### Завдання 3. Публікація образу в Docker Hub

1. Створіть власний public repository на [Docker Hub](https://hub.docker.com/), наприклад `surname-web`.
2. Увійдіть у Docker Hub через `docker login`.
3. Перетегуйте образ і опублікуйте його:

```bash
docker tag surname-web:2.0 DOCKERHUB_USERNAME/surname-web:2.0
docker push DOCKERHUB_USERNAME/surname-web:2.0
```

4. Перевірте завантаження образу:

```bash
docker pull DOCKERHUB_USERNAME/surname-web:2.0
docker run --rm --publish 8090:80 DOCKERHUB_USERNAME/surname-web:2.0
```

Не публікуйте паролі, access token або інші секрети у файлах і скриншотах.

### Результат роботи

Здайте:

- посилання на Docker Hub repository;
- змінені файли `Dockerfile` і `site/index.html`;
- скриншот вебзастосунку у контейнері;
- вивід команд `docker image ls` і `docker ps`;
- коротке пояснення призначення основних інструкцій Dockerfile.

## 3. Таблиця інструкцій Dockerfile

Dockerfile читається зверху вниз. Інструкції описують базовий образ, файли, команди збірки, параметри запуску та метадані контейнера.

| Інструкція | Призначення | Приклад | Важлива примітка |
|---|---|---|---|
| `FROM` | Вибирає базовий образ | `FROM nginx:1.27-alpine` | Обов'язкова перша інструкція; підтримує multi-stage build через `AS`. |
| `RUN` | Виконує команду під час побудови образу | `RUN apk add --no-cache curl` | Результат потрапляє у шар образу. |
| `CMD` | Задає команду за замовчуванням під час запуску | `CMD ["nginx", "-g", "daemon off;"]` | Може бути перевизначена аргументами `docker run`. |
| `ENTRYPOINT` | Визначає основний процес контейнера | `ENTRYPOINT ["/app/start.sh"]` | `CMD` може задавати аргументи для `ENTRYPOINT`. |
| `COPY` | Копіює локальні файли з build context | `COPY site/index.html /usr/share/nginx/html/` | Основний рекомендований спосіб копіювання файлів. |
| `ADD` | Копіює файли та може розпаковувати локальні архіви | `ADD assets.tar.gz /app/` | Для звичайного копіювання краще використовувати `COPY`. |
| `WORKDIR` | Задає робочу директорію | `WORKDIR /app` | Діє для наступних `RUN`, `CMD`, `ENTRYPOINT`, `COPY` і `ADD`. |
| `ENV` | Задає змінну середовища в образі та контейнері | `ENV APP_ENV=production` | Не використовуйте для паролів і токенів. |
| `ARG` | Задає змінну тільки під час build | `ARG VERSION=1.0` | Передається через `docker build --build-arg`; не призначена для секретів. |
| `EXPOSE` | Документує порт, який слухає застосунок | `EXPOSE 80` | Не публікує порт хоста; для цього потрібен `docker run -p`. |
| `USER` | Визначає користувача для команд і запуску | `USER nginx` | Запуск від непривілейованого користувача підвищує безпеку. |
| `VOLUME` | Оголошує точку монтування даних | `VOLUME ["/var/lib/app"]` | Дані мають окремий життєвий цикл від контейнера. |
| `LABEL` | Додає метадані образу | `LABEL org.opencontainers.image.title="web"` | Можна зберігати назву, версію, автора та адресу source code. |
| `HEALTHCHECK` | Визначає перевірку працездатності контейнера | `HEALTHCHECK CMD curl -f http://localhost/ || exit 1` | Код `0` означає успішну перевірку. |
| `ONBUILD` | Задає інструкцію для дочірнього образу | `ONBUILD COPY . /app` | Спрацьовує під час використання образу як базового. |
| `STOPSIGNAL` | Визначає сигнал для зупинки контейнера | `STOPSIGNAL SIGTERM` | Використовується, якщо застосунок потребує спеціального сигналу. |
| `SHELL` | Змінює оболонку для shell-формату команд | `SHELL ["/bin/bash", "-c"]` | За замовчуванням Linux використовує `/bin/sh -c`. |
| `# syntax=` | Вказує frontend для обробки Dockerfile | `# syntax=docker/dockerfile:1` | Parser directive розміщується на початку файлу. |
| `# escape=` | Задає escape-символ у Dockerfile | `# escape=\`` | Найчастіше використовується у Windows Dockerfile. |
| `#` | Додає коментар | `# Static site image` | Коментарі не виконуються. |

`MAINTAINER` застаріла. Для метаданих автора використовуйте `LABEL maintainer="..."`.
